# Contributing to Fluid Island

Thanks for considering a contribution. The project is at an early planning stage, so clear reasoning and small, reviewable proposals are more useful than large unrequested implementations.

## Before starting

1. Read the README and check existing issues and discussions.
2. For substantial changes, open an issue first to discuss the problem and proposed approach.
3. Keep pull requests focused. Explain the problem, the design choice, and how you validated the change.
4. Do not add telemetry, network services, background collection, or external dependencies without documenting the need and privacy implications.
5. Do not copy code, icons, fonts, screenshots, or other assets from third-party projects unless the license permits reuse. Record provenance and attribution.

## Development expectations

- Prefer clear, maintainable code over clever abstractions.
- Measure performance claims; do not describe something as faster without evidence.
- Document desktop-environment and session assumptions.
- Include tests or reproducible manual validation where practical.
- Avoid changing host configuration or introducing installation side effects as part of tests.
- Respect accessibility, keyboard navigation, reduced-motion preferences, and high-contrast settings.

## Pull request checklist

- [ ] The change has a clear purpose and scope.
- [ ] Relevant tests or validation steps are documented.
- [ ] Documentation is updated where needed.
- [ ] New dependencies and their licenses are explained.
- [ ] No secrets, personal data, or unrelated generated files are included.
- [ ] Third-party material has documented provenance and compatible licensing.
